# Contributing to GHCP Workshop

Thank you for your interest in contributing to the GHCP Workshop project!

## Getting Started

1. Fork the repository
2. Clone your fork locally
3. Create a new branch for your changes
4. Make your changes
5. Test your changes
6. Submit a pull request

## Development Setup

```bash
# Clone the repository
git clone https://github.com/yourusername/GHCP-Workshop.git

# Navigate to the project directory
cd GHCP-Workshop

# Install dependencies (if applicable)
# npm install
# or
# pip install -r requirements.txt
```

## Code Guidelines

Please follow the coding standards defined in [.github/copilot-instructions.md](.github/copilot-instructions.md).

### Key Principles
- Write clean, readable code
- Include tests for new features
- Update documentation as needed
- Follow existing code patterns
- Keep commits atomic and well-described

## Commit Messages

Follow the guidelines in [.github/prompts/commit-message.md](.github/prompts/commit-message.md).

Example:
```
feat(module): add new feature description

- Detailed explanation of changes
- Why this change was needed
- Any breaking changes

Fixes #issue-number
```

## Pull Request Process

1. **Before submitting:**
   - Ensure all tests pass
   - Update documentation
   - Follow code style guidelines
   - Rebase on latest main branch

2. **PR Description should include:**
   - Clear description of changes
   - Link to related issues
   - Screenshots (if UI changes)
   - Testing steps

3. **Review process:**
   - Maintainers will review your PR
   - Address review comments
   - Once approved, PR will be merged

## Testing

- Write tests for new features
- Ensure existing tests pass
- Aim for high test coverage

```bash
# Run tests
npm test
# or
pytest
```

## Documentation

- Update README.md for new features
- Add inline code comments for complex logic
- Update API documentation
- Add examples when helpful

## Code Review

When reviewing code:
- Be respectful and constructive
- Focus on code, not the person
- Explain your suggestions
- Acknowledge good practices

## Reporting Bugs

When reporting bugs, please include:
- Clear description of the issue
- Steps to reproduce
- Expected vs actual behavior
- Environment details (OS, version, etc.)
- Screenshots or error messages

## Feature Requests

When requesting features:
- Describe the feature clearly
- Explain the use case
- Consider potential alternatives
- Be open to discussion

## Questions?

If you have questions:
- Check existing documentation
- Search closed issues
- Open a new discussion
- Reach out to maintainers

## Code of Conduct

Please be respectful and professional in all interactions. We aim to maintain a welcoming and inclusive community.
